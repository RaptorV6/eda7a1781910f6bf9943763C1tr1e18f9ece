# Project map

## Project purpose
POC for proxying Citrix StoreFront / NetScaler explicit-auth login from a modern .NET 10 portal. Lets the portal drive Citrix programmatically without redirecting the user through StoreFront's UI.

## Two stacks on disk

### Active: `PortalComponent/` (ASP.NET Core 10.0)

```
PortalComponent/
├── PortalComponent.csproj      # net10.0, Razor Pages + minimal APIs
├── Program.cs                  # *** main entry point, all Citrix proxy endpoints + helpers ***
├── appsettings.json            # CitrixDiagnostics:BaseUrl, BodyPreviewLimit, etc.
├── appsettings.Development.json
├── Models/
│   ├── CitrixLoginRequest.cs        # explicit-login input
│   ├── CitrixLoginResponse.cs       # explicit-login output (verbose, all hops)
│   ├── CitrixProbeRequest.cs        # generic server-probe input
│   ├── CitrixProbeResponse.cs       # generic server-probe output
│   └── CitrixClientLogEntry.cs      # browser-side log forwarder shape
├── Pages/
│   ├── Index.cshtml(.cs)            # diagnostic UI host (Razor Page)
│   ├── Privacy.cshtml(.cs)
│   ├── Error.cshtml(.cs)
│   └── Shared/
├── Properties/                      # launchSettings.json
├── wwwroot/                         # static assets
├── bin/, obj/, publish/             # build artefacts (currently tracked — avoid)
```

### Reference: `Citrix/` (classic ASP.NET / IIS, do not edit)

```
Citrix/
├── Configuration/
├── FIS/                             # Global.asax, Views/, web.config, App_Data/
├── FISAuth/
│   ├── Certificate/
│   ├── HttpBasic/
│   ├── Integrated/
│   └── Views/, web.config, App_Data/
```

These directories are **captured StoreFront server material** used as ground-truth for what the upstream StoreFront expects. They are not an active codebase. Read them when you need to confirm the shape of an XML response, a form field name, or a `web.config` setting.

## Entry points

- **HTTP entry:** `PortalComponent/Program.cs` (top-level statements).
- **API endpoints:**
  - `POST /api/citrix-diagnostics/client-log` — browser → server log forwarder.
  - `POST /api/citrix-diagnostics/server-probe` — generic StoreFront request proxy with bootstrap.
  - `POST /api/citrix-diagnostics/explicit-login` — full StoreFront ExplicitAuth flow → Resources/List.
- **Razor Pages:** `Pages/Index.cshtml` is the diagnostic UI; `Pages/Index.cshtml.cs::IndexModel` reads `CitrixDiagnostics` config and exposes endpoint URLs to the page.

## Important modules

- `PortalComponent/Program.cs::CitrixAuthFormDefinition` — DTO for the parsed XML auth form.
- `PortalComponent/Program.cs::CitrixExplicitAuth` — static helper class. Key methods:
  - `CreatePageHeaders` — for navigation/bootstrap/meta-refresh hops.
  - `CreateBaseHeaders` — for StoreFront API calls.
  - `CreateRequest` — composes `HttpRequestMessage` with body/headers.
  - `TryParseAuthForm` — XML → `CitrixAuthFormDefinition`.
  - `TryParseAuthMethodUris` — extracts auth-method candidates from JSON or XML body.
  - `TryExtractMetaRefreshUrl` — regex for `<meta http-equiv="refresh">`.
  - `FindElementValue`, `FindAuthMessage` — XML field/error helpers.
  - `Preview` — clamp body to 1200 chars (configurable).
  - `GetCookieNames`, `GetCookieValue` — cookie inspection.

## Important config files

- `PortalComponent/appsettings.json` — `CitrixDiagnostics:BaseUrl`, `PanelTitle`, `BodyPreviewLimit`. Logging levels.
- `PortalComponent/appsettings.Development.json` — dev overrides.
- `PortalComponent/Properties/launchSettings.json` — local run profile.
- `.claude/settings.local.json` — pre-allowed Bash patterns (currently `dotnet build:*`).
- `.claude/settings.json` — hooks (reminder-only).
- `PortalComponent.sln` — solution; contains only the active project.

## Tests

None. See `commands.md`.

## Generated / build files (do not edit)

- `PortalComponent/bin/`, `PortalComponent/obj/`, `PortalComponent/publish/` — currently tracked in git, but content is generated by `dotnet build`/`publish`.
- `Citrix/**/bin/` — generated artefacts of the legacy classic-ASP.NET sites.

## Files Claude should be careful with

- `PortalComponent/Program.cs` — the whole Citrix flow lives here and the order of operations is load-bearing. Read [decisions.md](decisions.md) and [failed-approaches.md](failed-approaches.md) before refactoring.
- `Citrix/**` — read-only reference. Do not "modernise" or delete.
- Anything under `*/bin/`, `*/obj/`, `*/publish/` — generated.
- `appsettings.json` — contains an internal hostname; safe to commit but think before exposing the URL externally.

## Where to look for common tasks

| Task | File / location |
|---|---|
| Add a new StoreFront API call | `PortalComponent/Program.cs::CitrixExplicitAuth.CreateBaseHeaders` + new endpoint |
| Tune the bootstrap redirect chain | `Program.cs` explicit-login endpoint, hop loops |
| Add a new field parsed from auth form | `CitrixAuthFormDefinition`, `CitrixExplicitAuth.TryParseAuthForm` |
| Change body-preview length | `appsettings.json::CitrixDiagnostics:BodyPreviewLimit` (consumed by `Index.cshtml.cs`); helper default in `CitrixExplicitAuth.Preview` |
| Change the diagnostic UI | `Pages/Index.cshtml`, `Pages/Index.cshtml.cs` |
| Find what the upstream StoreFront expects | `Citrix/FIS*/Views/`, `Citrix/FIS*/web.config` |
| Permission-allow a new Bash command | `.claude/settings.local.json` |
